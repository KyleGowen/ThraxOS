# `upscale-banner` skill

Source: [`.agents/skills/upscale-banner/`](../../.agents/skills/upscale-banner/)

Resolves a simfile banner, stages faithful 836 x 328 preview options, and routes an entirely missing contained banner target with no usable fallback through `generate-banner`. It requires canonical title/artist/credit text in scratch-generated designs, renders exact approval evidence, binds approval to one selected hash, and performs a guarded replacement or source-less creation only after approval.

## Components

- `scripts/Inspect-Banner.ps1`: resolves and contains `#BANNER` within the song directory.
- `scripts/Normalize-GeneratedBannerPreview.ps1`: standard-decodes a generated image, preserves the raw original, strips problematic ancillary metadata, optionally flattens intended-opaque art with `-Opaque`, and writes a validated 836 x 328 PNG outside the live song root.
- `scripts/Format-BannerPreviewMarkdown.ps1`: independently decodes and hashes the authoritative image, emits a renderer-safe inline Markdown block, and automatically stages a byte-identical full-resolution copy under `.tmp/banner-preview-display/` when an external path cannot render inline; the native full-resolution link remains on the authoritative file.
- `scripts/Test-BannerPreviewMarkdown.ps1`: creates a disposable external-path fixture and proves the formatter uses a SHA-identical workspace display copy inline while preserving the authoritative native-file link; it also proves workspace images render directly without another copy.
- `scripts/Install-ApprovedBanner.ps1`: hash-binds and installs the approved preview; it refuses an open game or changed preview/source/simfile, preserves opaque 836 x 328 output, backs up any existing source/fallback, and reports `RollbackAction=RemoveCreatedTarget` when no original banner existed.
- `scripts/Update-BannerQueue.ps1`: maintains the fingerprinted queue, reads and writes it explicitly as UTF-8 without a BOM, rejects missing/blank/ambiguous/inconsistent `#BANNER` declarations, selects consistently referenced source-less targets as `generationMode=generate-banner`, serializes cross-process updates, preserves history, proves created targets, and retains installed-content history across refreshes.
- `scripts/Test-BannerInstallWorkflow.ps1`: disposable fully opaque RGBA fixture test for expected-hash refusal, rollback/hash evidence, opaque installed dimensions, unchanged simfile, and cross-process queue-lock waiting.
- `references/banner-conventions.md`; image editing capability; `memory/banner-upscale-queue.json` for scheduled state.

## Safety

Preview generation is staging-only and scheduled runs never install. Exact-preview approval is required. Never touch simfiles, audio, charts, scores, profiles, timestamps, signatures, or GrooveStats eligibility, and do not restart ITGMania.

A selectable song must still have one identical, nonblank, contained `#BANNER` declaration in every simfile. If that target and every decodable banner-shaped fallback are absent, the queue may select the fingerprint with null source evidence and `generationMode=generate-banner`; blank, missing, conflicting, or escaping declarations stay ineligible. The source-less preview shows a factual missing Before state rather than a fabricated image. A later approved install creates only the declared target, and restoring the prior state means deleting that new file.

Before any from-scratch or inspiration-based banner generation, parse trimmed `#TITLE`, `#ARTIST`, and optional `#SUBTITLE` from every `.sm` and `.ssc` in the song folder. Require one nonblank title and artist plus exact cross-simfile agreement. The generated banner must visibly and readably include the canonical song title, complete artist string, every featuring credit, and every remix/edit/mix/version label carried by those fields. Do not infer or shorten metadata. Missing, conflicting, misspelled, cropped, or unreadable required copy rejects the candidate.

Bare `install` applies only to the most recently displayed, explicitly labeled, queue-bound After in the same task. Never resolve it from global pending order or an unlabeled artifact. Interactive installs pass the queue's expected preview, source, and simfile hashes into the guarded installer; a source-less creation must also pass explicit `-SourceLessGeneration`. A lock timeout or hash mismatch stops the workflow instead of authorizing direct JSON or live-file edits.

Built-in image generation results must be forwarded with the runtime's generated-image result handler, not parsed as generic content blocks. A forwarding/staging failure does not consume a model attempt when the generated result remains recoverable. Always render the exact full-resolution source as `Before`, even on failure; render every exact staged result as `After` or `After A`, `After B`, and so on before requesting a choice. Build each response block by invoking `Format-BannerPreviewMarkdown.ps1` through `powershell.exe -NoProfile -ExecutionPolicy Bypass -File`; do not hand-write angle-wrapped Windows backslash paths inside image tags. For authoritative files outside the repository, the formatter uses a SHA-verified, byte-identical full-resolution workspace display copy only for the inline image and keeps the direct native-file link on the original. This is not a thumbnail, crop, re-encoding, proxy, or queue-binding change.

A broken inline placeholder with a working native-file link is a response-rendering failure, not a missing generation. Revalidate the authoritative file/hash plus the formatter's `DisplayPath` / `DisplaySha256`, require matching hashes, and re-emit the formatter output without another model call or queue transition.

If an inline generation and a saved-file inspection seem visually different, do not retry or rotate the queue from that impression alone. Hash and standard-decode the saved output, normalize it with `Normalize-GeneratedBannerPreview.ps1`, and inspect the normalized copy. Matching bytes or decoded pixels establish a recoverable result even if a vision pass describes it inconsistently; stage it for owner review rather than recording `output-handling-error`.

## Reproduce and verify

1. Adapt approved song roots and queue scope.
2. Run `Inspect-Banner.ps1` on a test simfile; confirm containment and dimensions.
3. For a scratch-generation fixture, require consistent nonblank title and artist metadata across every simfile, retain any subtitle/featuring/remix qualifiers verbatim, and confirm the output visibly includes all required copy. Reject missing/conflicting metadata and missing, altered, cropped, or unreadable generated text.
4. Run `Normalize-GeneratedBannerPreview.ps1` against a generated PNG; for an intended-opaque result, pass `-Opaque`. Confirm the raw input remains unchanged, the output decodes at 836 x 328 outside the live song root, opacity matches intent, and a visually disputed result is independently verified before any retry.
5. Run `Update-BannerQueue.ps1 -Refresh -SelectNext`; confirm never-attempted candidates are selected first, followed by returned candidates from least recently attempted, without duplicate fingerprints. Include a song whose `.sm` has a banner while its `.ssc` has blank `#BANNER:;`, and require that fingerprint to remain ineligible. Include a second song whose simfiles agree on one contained missing target and provide no fallback; require it to be eligible with `generationMode=generate-banner` and null source path/hash.
6. Validate staged 836 x 328 PNG output. Run `Test-BannerPreviewMarkdown.ps1`, then run `Format-BannerPreviewMarkdown.ps1` on the real external source. Require a workspace-contained `DisplayPath`, matching authoritative/display SHA-256, forward slashes, percent-encoded segments, no angle wrapper around the inline destination, decoded dimensions, and a direct native-file link to the authoritative source. Verify the response visibly renders the exact full-resolution `Before` plus every exact labeled After option. Test installation only after approval. Pass expected preview/source/simfile hashes, confirm the installer refuses stale hashes and an open game, then verify its original/backup/installed/simfile hash evidence, unchanged banner reference, and that an opaque preview remains fully opaque after installation.
7. Mark the pending record installed, refresh, and confirm the helper proves the live source equals the deterministic approved-preview rendering, follows an expected fallback-or-source-less transition to the new target, migrates terminal history plus installed-source hash, and rejects any other path or file mismatch. For source-less creation, require null original/backup evidence plus `RollbackAction=RemoveCreatedTarget`. Use `-RecordInstalledContent` for documented recovery and exercise concurrent fixture updates.
8. Recreate the optional automation from [its guide](../scheduled-tasks/hourly-misc-banner-upscale-queue.md).

Run `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .agents/skills/upscale-banner/scripts/Test-BannerInstallWorkflow.ps1` after installer, queue-lock, or queue-encoding changes. It verifies non-ASCII attempt-history round trips, creates and removes only a disposable temp fixture, and must never point at a live song root.

Failed generation, prompt mistakes, and ordinary preview rejection return the exact pending fingerprint with `-ReturnToQueue`, an outcome, and a nonblank note. This clears active preview state while preserving immutable attempt history and `lastAttemptedAt`. Explicit good-as-is feedback becomes fingerprint-scoped `skipped`, requires a factual `DecisionNote`, and does not require a preview; changed source or simfile content is assessed anew. Use terminal `denied` only when the owner explicitly opts that fingerprint out permanently.

Every terminal install, denial, or skip requires `-DecisionNote` so the queue preserves the owner's outcome and any supplied reasoning. After every run or interactive decision, perform the skill's retrospective: retain fingerprint-specific evidence in the queue, promote stable owner-wide preferences only with adequate evidence, and update the skill plus matching guides only for reusable, actionable lessons. Validate every skill edit. A run with no reusable lesson should not cause a fabricated skill change.
